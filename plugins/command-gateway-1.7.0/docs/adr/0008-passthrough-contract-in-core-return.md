# 执行后放行（passthrough）：放行动作放核心、契约放返回值

指令被认领后默认「不存档、不建会话」，1.4.0 起允许「执行后放行」：指令执行完把这条消息
按原文或改写后的文本放回正常聊天流程。我们决定：**放行动作由核心调用点执行**
（`run()` 返回 `{ passthrough }`，核心的 `releaseClaimed()` 存档 + 指令禁言检查 +
链接媒体转发 + 触发会话），而**不是**插件拿 `host.store` / `host.orchestrator` 自己重新注入。

## Considered Options

- **核心补丁 v4 读返回值（选定）**。放行路径与核心永远一致（`maybeTriggerCommandMute`、
  `forwardLinkedMedia`、未来的新逻辑不会漏）；原消息的 `media` 数组天然在手；
  外部拦截链插件免费获得同一契约。代价：`PATCH_VERSION` +1，用户要重启一次。
- **插件自行重注入**。不用动补丁、不用重启，但要重写一遍放行路径——上面两个核心动作
  都得复刻，`media` 数组插件侧拿不到（调用点没传），核心以后改放行逻辑时这里是静默负债。否掉。

## Consequences

- 补丁引擎需要「旧版本块原位升级」：标记还在、内容是旧版 → 状态 `stale` →
  按字节跨度摘旧插新（`removeBlockSpan`），与手工"摘→打"等效。
- 放行**不重新过拦截链**（防二次认领循环）；存档用消息原始时间戳，
  指令回执（`appendSelf`）先入档也不会造成历史错序。
- 裁决优先级：子插件返回值 > 清单声明 > 不放行；失败路径（抛错/超时/`ok:false`）
  缺省不放行，声明 `onFail: "release"` 才放。设置页**不参与**放行配置（开发者主导）。
