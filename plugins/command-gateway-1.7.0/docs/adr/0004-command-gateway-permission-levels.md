# 指令前置用权限等级表取代管理员布尔

**Status**: accepted

原来的权限只有「是不是管理员」两种状态（`admins` 逗号列表 + 一个"列表为空则人人都是管理员"的开关），接入项那边也只有 `allowAll`。要表达"这个人能用天气但不能用重启"就得给每类人各开一个名单，表达不了。现在改成一张**权限表**（`QQ → 0~100000 的整数`，第一行固定是「默认权限」，不在表里的 QQ 用它）+ 每个接入项一个**权限等级**，判定规则只有一条：`触发者等级 ≥ 接入项等级`。子插件的入参也从 `isAdmin` 布尔换成 `permission` 数字。

## Considered Options

- 保留管理员布尔、只加"白名单/黑名单"：表达不了分级，且每加一档就要多一份名单。
- 等级制但默认放开（新接入项等级 0）：跟"默认权限初始 0"组合起来，等于**任何新接入的指令所有人都能用** —— 敏感指令在配置完成前就已经对全群开放了。
- 等级制 + 默认收紧（本决策）：默认权限 0、新接入项等级 1，于是"没配过权限表 = 谁也用不了"。

## Consequences

- **默认是收紧的，且看起来像坏了**：刚接入一条指令后发出去毫无反应，是因为默认权限 0 小于该指令的等级 1。开发文档的启用步骤与失败对照表都专门写了这条。
- 权限不足时**不拦截、不回执**：消息当普通消息走聊天流程（与 ADR 0003 的 S2 一致）。用户看不出"这条指令存在但我不能用"，代价是不知道自己是没权限。
- `/帮助` 不设门槛，人人可用，但只列出**当前这个人**够得着的指令；因此低权限用户看到的通常就是「当前没有可用指令。」。
- `/帮助` 与 `/权限查询` 这两个**元指令**也各有一个可配的权限等级（默认 0 / 1），它们的指令词是保留词，接入项不许占用。
- `admins`、`anyoneWhenEmpty`、`allowAll` 三个字段直接删除，**不写迁移**：插件当时还没发布，没有真实存量数据；而"旧管理员该折成多少级"的映射是拍脑袋的，写下来只会得到一段无法验证的代码。
- 权限等级只影响"能不能触发指令"，与插件的能力权限（`permissions: ["web_fetch"]` 那套）是两回事，别混用同一个词。
